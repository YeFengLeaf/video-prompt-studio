# 项目差距分析与改造方案

- 分析日期：2026-10-20
- 对象：`提示词产品/`（网站 MVP）→ `视频提示词Skill/`（可分发 Skill）
- 原则：**只增不改**。现有 `app/` 一行不动，新成品独立目录，可随时回退。

现有产品真正值钱的三件事：
1. **台词逐字保真 + 时间轴对账**（`extract_dialogue` / `plan_durations` / `self_check`）；
2. **素材职责 + 作用镜头 + 引用语法隔离**（`_refs` / `build_assets` / SC-06–08）；
3. **证据分级与"不夸大成片质量"的表述纪律**（`knowledge.py` 的依据等级、导出 §7–8）。

这三件事恰好是社区 7 个样本里最普遍的缺口（见 `01_社区Skill调研报告.md` §6.5）。

## 3. 迁移原则

1. **加法优先**：新建 `视频提示词Skill/`，不改 `提示词产品/app/` 的任何文件。
2. **可回退**：改造前对 `提示词产品/` 做只读快照（见 §8）。
3. **规则不搬家，重写**：`knowledge.py` 的规则是给代码看的；Skill 的 references 是给模型看的，必须重写成"条件 + 反例 + 失败边界"。
4. **脚本只做确定性工作**：算术、结构对账、语法隔离；审美与叙事判断交给人/模型。
5. **证据随行**：每个平台数字必须带证据等级；没有来源的数字降级为 `C 未核实`。
6. **占位符保真**：模板里的 `{{variable}}` 原样保留，脚本校验，不擅自改名或删除。

## 5. 输入输出 Schema

### 5.1 输入（`assets/schemas/request.schema.json`）

```json
{
  "input_type": "idea | synopsis | script | storyboard | lyric | ad | nonreal",
  "text": "用户原文，逐字保存",
  "model": "seedance-2.0 | seedance-2.5 | veo | minimax-h3 | kling | generic",
  "delivery": "single | sequence | series",
  "duration_seconds": 15,
  "aspect": "16:9 | 9:16 | 1:1 | 4:3",
  "must_keep": ["台词原文", "品牌名", "禁用项"],
  "assets": [
    {"id": "A01", "type": "character|scene|product|prop|first_frame|video|audio",
     "role": "身份|空间|产品|运镜", "scope": ["S01-01"], "note": "文字描述或文件名"}
  ],
  "assumptions_allowed": true
}
```

约束：
- `text` 不改写；台词从 `text` 中逐字取。
- `assets` 只登记用户**实际拥有**的素材；待生成素材放 `pending_assets`，不进入引用。
- `assumptions_allowed=true` 表示可用默认值推进，并在决策摘要标注。

### 5.3 计划（`assets/schemas/plan.schema.json`）

多镜/多集项目用 `plan.json` 记录段落、镜号、时长、出点状态与素材绑定；单条 Fast Lane 不需要。

```json
{
  "project_id": "proj-001",
  "model": "seedance-2.0",
  "aspect": "16:9",
  "status": "planned",
  "segments": [
    {"id": "S01", "duration": 15, "shots": [
      {"id": "S01-01", "t0": 0, "t1": 5, "size": "全景", "move": "缓推",
       "action": "角色推门进入", "exit_state": "门半开，人站在门内左侧"}
    ]}
  ],
  "assets": [
    {"id": "A01", "name": "主角-正面", "role": "identity", "scope": ["S01-01"]}
  ]
}
```

`status` 只允许 `planned / assets-ready / submitted / generated / reviewed`；没真跑过就不许往前标。

## 6. 模板分层与组合机制

### 6.1 三层

| 层 | 解决什么 | 组合方式 |
|---|---|---|
| `base/` | 片子类型（剧情/广告/MV/纪录/非写实） | 选 1 个 |
| `styles/` | 视觉语法（写实/水墨/赛博/纸艺/动漫/定格） | 选 0–1 个，叠在 base 的 `style_anchor` |
| `shots/` | 镜头模式（建立/正反打/跟拍/一镜/产品环绕/变身） | 按分镜需要选 1–N 个 |

**组合规则**：
- base 必选；styles 可选；shots 按镜选。
- 组合时只替换 `{{}}` 变量，不改骨架里的固定句式。
- 同一个 `{{}}` 在多处出现时，必须填同一个值（脚本会提示重复）。
- 非写实 base 禁止叠加写实 styles（`paper-craft` 与 `cinematic-realism` 互斥）。

### 6.2 模板四字段（借自 S5）

```yaml
useWhen: 什么时候用
structure: 骨架顺序
guidance: 填写规则
pitfalls / 常见失败: 反例与修法
```

**没有匹配模板时明说，从第一性原理写**，不强套。

## 9. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 两套规则漂移（app 与 Skill） | 同一输入两种结论 | Skill 明确"不依赖 app"；app 继续按原验收；需要合并时以 Skill 的 references 为准 |
| 模板膨胀 | 维护成本上升 | 只保留 17 个；新增模板必须过 `check_templates.py` |
| 模型参数过期 | 误导用户 | 参数表带证据等级与核验日期；`C` 级必须提示 |
| 脚本误报 | 用户不信任 | 脚本只守结构不变量；语义项一律标"人工" |
| 无 git 回滚 | 误删难恢复 | 新增目录独立；建议尽快 `git init` |

## 10. 验收标准

1. **3 轮闭环**：第 1 轮一句话 + "你定" → 第 2 轮出 8 节包 → 第 3 轮只改一镜，其余逐字不变。
2. **样例可复现**：4 个样例全部 `check_package.py` 14/14 PASS。
3. **方言隔离**：Seedance 包用 Veo 校验必须报 S-08 FAIL（负向测试）。
4. **占位符**：17 个模板 223 个占位符全部保真；包内残留 `{{}}` 必须 FAIL。
5. **换模型**：事实层与分镜表逐字不变，只改执行层五处。
6. **诚实性**：每个未核实项在参数节标 `C/D`；不出现"保证成片质量"。
