# 04 · 素材与引用

> 核心：**每份素材只有一个主职责，每个维度只有一个所有者。**
> 没有素材也能出包，但不能伪造引用。

---

## 1. 素材类型与职责

| 素材类型 | 能控制什么 | 不能控制什么 |
|---|---|---|
| 角色图 | 身份、脸、发型、服装、体型 | 动作、镜头、场景 |
| 首帧图 | 开场构图、机位、光线、人物姿态 | 后续动作、镜头运动 |
| 尾帧图 | 收束构图与状态 | 中间过程 |
| 场景图 | 空间布局、材质、光源位置 | 人物走位 |
| 产品图 | 外形、颜色、材质、logo 位置 | 使用场景、人物互动 |
| 参考视频 | 运镜、动作节奏、剪辑节拍 | 人物身份（除非同时给角色图） |
| 音频 | 音色、台词节奏、BGM | 画面 |

**一份素材一个主职责**。同一张图可以兼管"身份 + 服装"，但不能同时管"身份 + 场景 + 运镜"——模型会串。

---

## 2. 职责矩阵（每维度只能有一个所有者）

| 维度 | 所有者 | 不得传递 |
|---|---|---|
| 身份 | 角色图 A | 服装、场景 |
| 服装 | 角色图 B 或文字 | 脸 |
| 空间 | 场景图 C | 人物 |
| 产品 | 产品图 D | 场景、人物 |
| 运镜 | 参考视频 E | 人物身份、场景 |
| 节奏 | 参考视频 E / 音频 F | 具体动作 |
| 光线 | 场景图 C 或文字 | 色温之外的东西 |

**规则**：
- 一个维度两个所有者 → 先删一个，再写提示词。
- 某份素材到最后没分到任何维度 → 从挂图清单删掉，不要"上传了但没用"。
- 明确写"不得传递"：`@Image1 只提供脸与发型，不传递服装与背景`。

---

## 3. 作用镜头（scope）

每个素材必须写生效范围，三种写法：

- `全部`：全片通用（角色身份、固定场景）
- 镜号范围：`S01-01 ~ S01-03`
- 稳定编号：`S02-01`

**禁止**：
- 空范围默认扩成全片（会让无关人物进入每一镜）；
- 范围写错还继续生成（标出来让用户改）；
- 每镜把所有人物都挂上（"全员到场"是引用混乱的头号原因）。

---

## 4. 编号与稳定 ID

```text
A01、A02…    资产身份（跨条稳定，不随上传顺序变）
S01、S02…    条（segment）
S01-01…      镜（shot）
```

- 资产编号在项目内**永不复用**；删掉的编号留空。
- 每条的**上传槽位**从 1 重新编号（平台的 `@Image1` 是本条第 1 张图），但资产身份仍是 A01。
- 生产包里必须同时给"资产编号"和"本条槽位"，否则用户会挂错图。

---

## 5. 引用语法隔离

| 模型 | 正确写法 | 禁止写法 |
|---|---|---|
| Seedance | `@Image1` / `@Video1` / `@Audio1` | `@element1`、`图1` |
| Kling | `@Element1` / `@Image1` / `@Video1`（Kling 4.0 官方指南，2026-10-27 复核） | `图1` |
| MiniMax H3 | `<Picture 1>` + `[Shot N]` | `@Image1` |
| Veo | 自然语言："the woman in the reference image" | `@Image1` |
| 通用 | `参考图1` | 平台专属语法 |

**混用语法是最常见的低级错误**：同一段里出现 `@Image1` 和 `<Picture 1>`，模型会忽略其中一个。

---

## 6. 首帧 / 尾帧

### 首帧（I2V）
- 首帧是**事实源**：身份、服装、构图、光线以图为准。
- 提示词只写"相对首帧的后续变化"：动作、运镜、表情变化、环境变化。
- **不要复述首帧里已经有的外貌**——重复描述会让人物漂移。
- 单镜内不改机位、不换视角；需要换就切镜。

### 尾帧（FLF2V）
- 首尾帧之间的过程要写"可观察的中间状态"，不能只写"从 A 到 B"。
- 落点必须精确对准尾帧：姿态、道具位置、机位、光线。
- 中间不要出现尾帧里没有的新主体。

---

## 7. 没有素材时怎么办

不是"不能做"，是"换个交付口径"：

1. 出**文本分镜草案**，明确写"待配资产"；
2. 不写 `@Image1`，不假装用户有图；
3. 给出**资产需求清单**：需要几张、每张什么职责、什么画幅；
4. 用户后续补图时，第 3 轮只改挂图节，不动故事层。

**禁止**：编造"图1 是你的主角"、声称"已分析你的参考图"。

---

## 8. 素材质量红旗（先修图，再写提示词）

| 红旗 | 后果 | 处理 |
|---|---|---|
| 水印 / logo / 乱码文字 | 被带进每一帧 | 换干净素材，别指望负向词擦掉 |
| 手部畸形 / 多指 | 沿用到视频 | 修图或换图 |
| 构图裁切过紧 | 运镜没有空间 | 换更宽的图 |
| 主体太小 | 身份锁不住 | 换近景角色图 |
| 多人物同框的身份图 | 第二个人混入 | 一人一张 |
| 光线方向矛盾 | 视频里光源乱跳 | 统一光源逻辑或分镜使用 |

**规则**：参考图里已经"烧进去"的问题，负向提示词救不回来。先修素材，再谈提示词。

---

## 9. 挂图清单格式（输出合同 §5）

```markdown
| 编号 | 素材 | 主职责 | 作用镜头 | 不得传递 | 本条槽位 |
|---|---|---|---|---|---|
| A01 | 主角正面半身 | 身份+发型 | 全部 | 服装、背景 | @Image1 |
| A02 | 雨夜街道 | 空间+光源 | S01-01~03 | 人物 | @Image2 |
| A03 | 产品瓶身 | 产品外形 | S01-03 | 场景 | @Image3 |
```

用户按"本条槽位"上传，就不会挂错顺序。

## 10. 首帧质量六条门槛与多图分工协议

> 来源：方法论设计案 §A3（首帧六条门槛 + 多图分工协议）。证据等级：本节内容为项目内约定（C 级），首帧门槛第 6 条在设计案中标注为 B 级证据（Seedance 平台合规）；未在当前模型上实测，一律标「未核实」，不得写成官方事实。

### 10.1 首帧质量六条门槛

首帧是图生视频的起点：模型从这一帧「演」出去。六条全部达标才能用作首帧；任何一条不达标，先修图再生成，不得用「提示词里补一句」代替。

| # | 门槛 | 怎么判断是否达标 | 不达标的典型表现 |
|---|---|---|---|
| 1 | 主体占画面 30–70%，无裁切关键部位 | 打开图量一下：主体最宽处 ÷ 画面宽在 0.3–0.7 之间；逐项点名关键部位（头、手、脚、道具、载具边缘）全部在画框内，无一处被边框切断 | 主体只占一角（模型会自己「脑补」放大，构图漂移）；手/脚被裁（生成后肢体从画框外「长」出来，形态错误） |
| 2 | 光线方向与目标场景一致 | 在图上画一条光线方向线（看阴影落点与高光面）：方向与分镜表里该镜的光位描述一致；同一空间内所有阴影朝同一方向落 | 首帧是左侧光、提示词写右侧黄昏光：模型在两者之间摇摆，出现双光源、阴影朝向打架 |
| 3 | 起始动作 / 姿态清晰（AI 从此帧演出去） | 能用一句话说清「这一帧正在发生什么动作」且无歧义；身体关节朝向、视线方向、手的抓握对象都看得清，不靠猜 | 姿态含糊（站着还是正要坐下分不清）：模型随机选一个演法，与下一镜的入点接不上 |
| 4 | 色彩在 STYLE LOCK 范围内（无过度饱和 / HDR） | 与 STYLE LOCK 壳并排对比：主色相、饱和度落在其描述范围内；无荧光色、无 HDR 式高光溢出 | 首帧已偏离色板：整段色调被首帧带跑，后面再用 STYLE LOCK 也拉不回来 |
| 5 | 关键区域（面部 / 手部）≥ 标清 | 放大到 100% 看面部与手部：五官轮廓、手指根数与朝向可辨认，无糊成一片、无多指粘连 | 面部/手部糊：生成后五官在运动中崩坏，且无法用差量句定点修复 |
| 6 | 无写实真人脸部（Seedance 平台合规，B 级证据） | 图中无可识别的写实真人面部；需要人脸时用风格化/遮挡/背影处理，或走平台允许的真人授权路径（见 `SKILL.md` §0 第 4 条安全边界） | 写实真人脸直接作首帧：平台合规风险，生成被拒或下架 |

**六条的关系**：1–5 条是质量门槛，6 条是合规门槛。质量不达标可以修图重来；合规不达标必须换处理方式，不得「先试试」。

### 10.2 多图分工协议（每维度一个 owner）

```text
@Image1 → 场景锚（背景 / 光线 / 空间几何）
@Image2 → 角色锚（人物外观，仅该角色出现时）
@Image3 → 色卡锚（仅色卡图，无其他内容）
@Image4 → 姿态参考（弱锚，「仅身份参考非首帧严格复刻」）
禁止：同一张图兼任多职
```

**分工规则**：

1. 每张引用图在提示词里只承担一个职责，并在引用处写明职责；引用语法按目标模型（`@Image1` 为 Seedance 系方言，其他模型用各自语法，分工角色本身与模型无关）。
2. 角色锚只在该角色出现的镜头引用；角色不出场的镜头不挂角色锚，防止「跨段污染」（角色幽灵般出现在不该出现的镜头里）。
3. 姿态参考是弱锚：只锁身份不锁动作，必须写明「仅作身份参考，非首帧严格复刻」，否则模型会照抄参考图的姿态，动作演不出去。
4. 引用图失效时靠文字清单兜底：锚定图 + 文字造型清单双保险（图挂了仍有文字），每镜的最小造型锚不得省略。

> **矛盾注记（两处来源不一致，如实记录）**：一处来源记载，色卡锚在旧项目中已被决定取消，颜色一致性改靠材质描述 + 光色铁律；而设计案 A3 的分工协议仍保留 `@Image3 → 色卡锚`。本文件按设计案保留该行，但标注为**项目约定、待确认**：使用色卡锚前须在决策摘要写明采用的是哪一种口径，不得同时混用两套说法。

### 10.3 反例：同一张图兼任多职的问题

**反例**：只给一张图，既当场景锚（要锁背景与光线），又当角色锚（要锁人物外观），还当色卡锚（要锁全片色调），提示词里写「严格按此图渲染背景、人物与色彩」。

**为什么出问题（协议推理，C 级约定，非实测结论）**：

1. **指令打架**：同一张图的三个职责互相牵制，任一处微调都会被其他职责拉回，结果是三处都只做到一半。
2. **内容泄漏**：色卡锚要求「仅色卡图，无其他内容」。一张有场景和人物的图被当成色卡用，图里的人物轮廓、建筑线条会作为「色彩信息」的一部分被模型吸收，下一镜出现不该有的残影或构图元素。
3. **责任无法定位**：出问题后无法判断是哪一维度的锚失效——换掉这张图，三个职责一起变；修提示词时不知道该改哪一句。
4. **弱锚被当强锚**：姿态参考图若同时兼任首帧，模型会把「仅身份参考」理解成「严格复刻」，动作被参考图锁死。

**正确做法**：按职责拆图。没有现成图时，宁可某个职责只用文字清单（写清空间/造型/色调），也不把一张图硬塞进两个职责；缺的图记入素材待办，不得用兼任代替。

## 11. 资产命名规范与质量标签

> 来源：方法论设计案 §A4（通用命名规范 + 质量标签体系）。证据等级：全部为项目内约定（C 级），未在当前模型上实测，标「未核实」。

### 11.1 命名格式

```text
格式：{类型}_{3位编号}_{2-4词描述}_{可选关键参数}
类型：CHAR / SCENE / PROP / CREATURE / STYLE / VOICE
示例：CHAR_001_主角_冷峻短发东亚男
      SCENE_002_废弃工厂_工业朋克夜景
      STYLE_001_LOCK_电影胶片暗黑志怪
      VOICE_001_主角_低哑温和中年男声
```

**规则**：

1. **编号自增、永不复用**：同一项目内资产按创建顺序自增（001、002……）；资产删除后编号不回收、不重排，避免旧生产包里的引用指到新资产上。
2. **描述 2–4 个词**：人类可读名即数据库检索键。描述写「是什么 + 关键区分特征」，不写剧情、不写情绪标签（情绪是镜头的事，不是资产的事）。
3. **关键参数可选**：只写影响复用的硬参数（例如画幅、光位、型号），不写风格形容词堆叠；风格归 STYLE 资产管，不进 CHAR/SCENE 的名字里。
4. **类型与引用语法一致**：生产包里引用资产时用同一编号（`@[CHAR_001_…]` 或目标模型的引用语法，见 `references/03`），不得在提示词里另起别名；别名只会让跨镜复用断链。
5. **新增资产在首次使用前注册**：新物件/新人物先有注册表条目与母图提示词，再进分镜。分镜里出现未注册资产，视为结构自检不通过。

### 11.2 目录结构（本库约定，C 级）

```text
assets/
├── CHAR/                  # 角色：人设四视图 + 母图 + 变体（湿身/换装/去外套）
│   └── CHAR_001_主角_冷峻短发东亚男/
│       ├── master.png     # 母图（母图提示词 ≤1024 字符，见 §11.3）
│       ├── views_4.png    # 四视图（9:16，单侧光；含一张无脸全身，见 references/08 §2 M4）
│       └── variants/      # 变体图（每张变体注明相对母图的差量）
├── SCENE/                 # 场景：空间布局 / 材质 / 光线
├── PROP/                  # 道具：灰底物料图 + 材质/旧化细节（可复用资产）
├── CREATURE/              # 生物：与 CHAR 同等对待（造型 + 动作特征）
├── STYLE/                 # 风格壳：STYLE LOCK 文本 + 色卡（如用色卡锚，见 §10.2 矛盾注记）
├── VOICE/                 # 音色池：.mp3 音色参考 + 首登场音色描述文本
└── registry.md            # 注册表：编号 + 名字 + 类型 + 状态（已有 / 待生成）+ 首次使用位置
```

**规则**：

1. **一资产一目录**：同一资产的所有图、变体、音色参考放在同一目录下，不得散落；目录名即资产全名，改名即改注册表，两处同步。
2. **注册表是唯一事实源**：`registry.md` 记录每个资产的状态（已有/待生成）与首次使用位置（第几段/第几镜）；生产包的素材挂图节与注册表逐项对账，对不上先补注册表再出包。
3. **母图与变体分离**：变体（换装、湿身、旧化）不得覆盖母图；变体目录里写明差量（相对母图改了什么、其余不动）。
4. **音色与造型同等锚定**：音色参考（`.mp3`）与四视图一样进资产库；首登场角色在首段写详细音色描述并注明「同时将本条作为音色参考入库」，之后只引用音色参考编号（见 `references/05` §10）。

### 11.3 母图提示词硬规格

1. **母图提示词不超过 1024 字符**。超长先删装饰词，不得删造型清单与否定清单。
2. **一次性复制块**：母图提示词做成一个可整块复制的纯文本块，块内只有提示词本体 + 尾部参数，说明与注释一律放块外；具体生成工具的语法以目标平台为准。
3. **每条视频提示词独立自足**：不写「如前述」「上面那个动作」；出场人物每人一句最小造型锚，场景一句带空间关系，时间写死第几镜第几秒，衔接用一句「承接上一镜尾帧」（如有尾帧图）。

### 11.4 质量标签体系（判定口径，全部须留记录）

| 标签 | 含义 | 判定口径 |
|---|---|---|
| 🥇 金标 | 多模型多场景验证通过 | 同一资产（壳/基准句/方法）在 ≥2 个模型 × ≥2 类场景下产出可用结果，且验证记录可查；仅「用过一次效果好」不得升金标 |
| 🥈 银标 | 单一场景验证通过 | 在 1 个项目 / 1 类场景下验证通过，方法卡须写明来源、适用场景与局限性；跨场景使用前须降级为「待验证」对待 |
| ⚪ 待验证 | 已创建，未实测 | 已写入资产库但无任何验证记录；生产包引用时必须标「未核实」，不得当作已验证资产交付 |

**升降级规则**：

1. 升级只凭验证记录，不凭主观评价；记录须写明模型、场景、日期与结果（可用/不可用 + 一句话原因）。
2. 模型或平台改版后，金标/银标资产进入「需复核」状态：复核通过恢复标签，复核失败降级，不得沿用旧标签交付。
3. 银标方法跨场景迁移时，只迁移规则本身，不迁移源场景的题材绑定（题材绑定留在「局限性」里，不得删）。

## 12. 人物一致性（视觉身份证 + 方案对比 + seed/recipe）

> 来源：外包一致性证据中的人物/LoRA/seed/recipe 项（REC_025–033、037–039，等级见各条）+ 锚定资产通用逻辑（源项目专名已去除）。每条主张带来源与等级；C/D 级标「未核实」。

### 12.1 视觉身份证模板（可填写，逐字复用）

**用法**：填好后整块逐字粘贴进每一镜的提示词，**禁止 paraphrase**——同义词分词会被模型当成不同角色（REC_037，D 级，未核实）。身份块一经审批通过即冻结，改动只改镜头专属指令（REC_039，B 级）。

```markdown
## 视觉身份证 · <角色名>（冻结版 v__，审批日期 __）

- 外形锚（逐字块）：<年龄段>，<脸型/五官>，<发型/发色>，<体型/身高>，<标志性细节，如疤痕/配饰>——每次生成原样粘贴，不得改写措辞。
- 服装锚：<上衣/下装/鞋/配饰，含材质与旧化>；换装时只改本行，并注明换装镜号。
- 参考图集（3–8 张）：<正面 / 三分之四 / 侧颜 / 全身 / 特征特写 / 关键光照变体>，每张编号 A01…，并注明"3 个好角度优于 5 个相似正脸"。
- 声音锚：见 `references/05_声音与台词.md` §10 音色身份证（同名同编号）。
- recipe 卡：模型 __ / 版本 __ / 分辨率 __ / 比例 __ / seed __ / 身份串逐字记录（见 §12.4）。
- 回锚规则：每 3–4 镜与参考图集比对一次，漂移立刻重生成，不带病往下传（REC_038，D 级，未核实）。
```

**锚定三件套**：场景锚（锁背景）/ 角色锚（锁人并隔离镜头范围，防跨段污染）/ 道具锚（锁物）——锚定写法 = 资产引用 + 精确造型清单 + 严格按图渲染 + 仅指定镜头范围出现。图挂了仍有文字清单双保险：锚定图 + 文字清单同时写。

**独立自足纪律**：每条提示词不写「如前述」「上面那个动作」；出场人物每个都带一句最小造型锚（资产引用或一句文字造型清单）；场景一句带空间关系；时间写死第几镜第几秒；与前镜衔接用一句「承接上一镜尾帧」（如有尾帧图）。

### 12.2 四方案对比表

| 方案 | 做法 | 成本 | 适用 | 局限 | 证据 |
|---|---|---|---|---|---|
| 参考图集 + 逐字身份块 | 3–8 张多角度参考图 + 冻结身份文本逐镜粘贴 | 低（无需训练） | 单条/短链、快速迭代 | 长片跨镜仍会漂移，需每 3–4 镜回锚 | REC_037 D 未核实；REC_039 B |
| recipe 卡片 | 模型/版本/分辨率/比例/seed/身份串逐字记录，逐镜复现 | 低（记录成本） | 同模型同版本内的批量复现 | seed 与 recipe 只在同模型同版本内有效，升级即漂移 | REC_038 D 未核实；REC_026/027 A |
| 角色 LoRA 训练 | 单角色几十张图训练 LoRA，推理挂载锁定人脸/造型 | 高（数据+GPU+调参） | 长片/系列、同一角色反复出现 | 训练集覆盖不全则新场景脸飘；视频 LoRA 参数不可照搬图像 LoRA | REC_025 A；REC_029 A；REC_031 D 未核实；REC_032 D 未核实 |
| 首尾帧 / 强帧衔接 | 相邻镜头用上一镜最强静帧或首尾帧控制引导 | 中（多一次生成） | 跨镜衔接、动作连续 | 参考图能力边界随平台版本变化；不保证一致性，须人工复查 | REC_039 B；REC_024 B |

**组合建议**：默认用方案 1 + 方案 2（参考图集 + recipe 卡）；长片/系列再评估方案 3；跨镜衔接困难时叠加方案 4。四方案可叠加，不互斥。

### 12.3 LoRA 训练要点（只写证据有的）

- 事实标准脚本集：sd-scripts，单角色几十张图训练角色 LoRA，推理按 0.6–0.8 强度加载；caption 用触发词 + 主体描述、去掉背景词（REC_025，A 级）。
- 冒烟测试：先跑 step-0，before/after 应完全相同；~50 条小数据先试，留 3–4 条验证片（REC_029，A 级，LTX 语境）。
- 参数纪律：rank 拉高到 128/256 时必须同步调 alpha（PEFT `use_rslora=True` 按 alpha/sqrt(rank) 修正），否则有效学习率反而下降（REC_029，A 级）。中文工程实测甜点（单卡，**不可外推其他模型**）：rank16 / 学习率 8e-5 / 16 轮，样本 ≥20 条，融合系数 0.45–0.7，>0.8 崩坏、<0.4 不生效（REC_031，D 级，未核实）。
- 数据集覆盖：训练前覆盖全剧所需的全部角度与光照；相似场景脸对、新场景脸飘是最典型失败（REC_032，D 级，未核实）。Wan2.2 流程：15–25 张多角度多光照图 + 唯一无意义触发词 caption，推理强度 0.7–0.8 起调（REC_033，C 级，未核实）。
- 诊断清单（fal 托管 trainer 语境）：验证片酷似训练数据 = 过拟合（减 steps/rank、增多样性）；LoRA 几乎不起作用 = 欠拟合（加 steps/rank、改善 caption）（REC_030，B 级）。
- 图像侧边界：sd-scripts 只覆盖图像侧 LoRA，视频 LoRA 需 MusubiTuner 等专用脚本（REC_025，A 级）。ComfyUI 中 Wan2.1/2.2 首尾帧 + 外挂 LoRA 是开源首尾帧一致性工作流的主力实现；wrapper 不增强身份保持（REC_024，B 级）。
- 肖像授权：用真人照片做参考涉及肖像授权，须取得授权（REC_037，D 级，未核实）。

### 12.4 seed 与 recipe 卡（边界先行）

- seed 是同一模型内复现的唯一锚点；跨模型/跨模态 seed 数字完全不通用（REC_026，A 级）。官方定义：同 seed + 同参数即逐位复现输出；确定性只在完全相同的权重版本、采样器、步数、调度器下成立（REC_027，A 级）。
- 视频 seed 复现性天然弱于图像 seed：运动对微小数值差极敏感，首帧近乎相同的两镜到第 3 秒会走向完全不同的运镜；不少热门视频模型根本不暴露 seed 控件（REC_028，D 级，未核实）。
- 操作法（REC_026，A 级）：出好片后立即记录 seed + 完整参数作 recipe；锁定 seed 每次只改一个变量做对照；探索期随机 seed、定型后锁 seed。**不得**把一个模型的好 seed 搬到另一模型想复现镜头——跨平台一致性靠参考图/首尾帧，而非 seed 搬家。
- recipe 卡模板：

```text
recipe：模型 __ 版本 __ / 分辨率 __ / 比例 __ / 时长 __ / seed __ /
参考图集 __ / 身份串（逐字）__ / 提示词（逐字）__ / 生成日期 __
```

跨模型切换时身份块文字逐字不变，只改引用语法与参数位置（见 `references/03_模型适配.md` §13；验收用 `scripts/check_switch.py`）。
