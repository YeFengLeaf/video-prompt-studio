## 1. 发布定位（一句话）

> 把一句创意或一段剧本，在 3 轮内变成**可执行、可审计、多模型适配**的视频提示词生产包；不生成视频，不承诺成片质量。

**对外只主张三件事**：
1. 3 轮内出 8 节生产包（不是一句提示词）。
2. 换模型只重编译执行层，故事层逐字不变。
3. 自带结构自检与证据等级，未核实项必须显示。

**不主张**：一键高质量、保证过审、替代导演、真实生成效果已验证。

## 6. GitHub 建仓与打包步骤

> **只在该目录内初始化 git**，不要在 `D:\AIGC知识库` 根目录 `git init`——根目录有 128MB 视频、私密凭据路径和大量制作素材。

```bash
cd 视频提示词Skill

git init -b main
git add .
git commit -m "feat: video-prompt-studio v1.0.0"

# 发布前再跑一次
python -X utf8 scripts/selftest.py

git tag -a v1.0.0 -m "video-prompt-studio v1.0.0"
git remote add origin git@github.com:<your-name>/video-prompt-studio.git
git push -u origin main --tags

# 打包（不含 .git）
mkdir -p dist
git archive --format=zip --prefix=video-prompt-studio/ \
  -o dist/video-prompt-studio-v1.0.0.zip v1.0.0

# Windows 校验和
Get-FileHash dist/video-prompt-studio-v1.0.0.zip -Algorithm SHA256 |
  ForEach-Object { "$($_.Hash.ToLower())  video-prompt-studio-v1.0.0.zip" } |
  Set-Content dist/SHA256SUMS
```

发布前检查：

- [ ] `git status` 干净，无 `__pycache__`、无 `.env`、无个人路径
- [ ] `LICENSE`、`README.md`、`CHANGELOG.md` 在根目录
- [ ] zip 解压后目录名为 `video-prompt-studio/`，与 frontmatter `name` 一致
- [ ] 解压到空目录后能跑 `python -X utf8 scripts/selftest.py`
- [ ] tag 指向的 commit 与 zip 内容一致（`git archive` 保证）

## 7. 发布文案

### 7.1 短版（即刻 / 小红书 / X）

> 我把"写视频提示词"做成了一个 Skill：
> 一句话或一段剧本 → **3 轮**拿到 8 节生产包（分镜表、逐条提示词、素材挂图、参数证据等级、自检）。
> 支持 Seedance 2.0/2.5、Veo、MiniMax H3 的方言；Kling 为实验性、未核实。
> 不生成视频；平台参数未逐台实测，未核实项会标出来。
> 附 6 个可复现样例，MIT。

### 7.2 长版（知乎 / B 站简介）

> 社区里的视频提示词 Skill 分两类：单文件手册（易用但无状态、无自检）和大套件（完整但 29 个子技能、单条创作者用不起）。
> 这个 Skill 走中间路线：一个入口、3 轮契约、8 节固定输出、6 种模型方言、17 个可组合模板、3 个确定性校验脚本。
> 它解决的不是"写一句更华丽的提示词"，而是"把创意变成能执行、能核对、能换模型的生产包"。
> 边界写死在文档里：不生成、不保证成片、平台参数未实测。

### 7.3 禁止用语

- "一键生成高质量视频"
- "保证过审 / 不限流"
- "替代导演 / 替代分镜师"
- "已实测所有模型"
- "3 轮保证出片"

## 9. 风险与回滚

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 平台参数过期 | 用户反馈时长/参考数不符 | 24h 内改 `03_模型适配` 证据等级，发 v1.0.1 |
| 用户以为能生成视频 | issue 问"视频在哪" | README 首屏加粗边界；演示视频开头说明 |
| 多段/多集误判复发 | S-02/S-03 FAIL 争议 | 已加回归；要求附包复现 |
| 许可异议 | 第三方指出结构/文案相似 | 立即下架相关段落，保留自写内容，公开说明 |
| 安装失败 | 目录名/客户端差异 | 提供 `install.md`；支持手动贴 `SKILL.md` |
| P0 缺陷 | 数据错误/无法运行 | 48h 内 v1.0.1；必要时把 v1.0.0 标为 pre-release |

**回滚步骤**：

1. GitHub Release 把 v1.0.0 标为 `pre-release`，保留 tag 与 zip（不删历史）。
2. 发布 v1.0.1，Release Notes 写清"修复什么、影响谁"。
3. 若属结构性问题，暂停社区分发，只保留仓库与 issue 通道。
4. 不 force-push tag；不覆盖旧 zip。
