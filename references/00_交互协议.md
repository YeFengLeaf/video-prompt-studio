# 00 · 交互协议

> 目标：**3 轮内交付**，且用户永远不需要回答专业问题。
> 本文件只在第 1 轮、建项目状态、或用户说"继续/下一集"时读。

---

## 1. 三轮契约的边界

| 轮次 | 允许发生 | 不允许发生 |
|---|---|---|
| 第 1 轮 | 收内容；问 ≤3 个阻塞问题；给默认值 | 让用户选风格/镜头/音色；要求填表；分批追问 |
| 第 2 轮 | 交完整 8 节生产包；标注默认值与未核实项 | 只给一句提示词；给 A/B/C 三版让用户挑 |
| 第 3 轮 | 只改点名单元；重跑结构自检 | 顺手优化别处；改镜号；推翻已确认决定 |

超过 3 轮仍没出包，说明第 1 轮问错了问题。**回退检查**：
- 是否在问技术细节？（不该问）
- 是否在等用户确认本可默认的东西？（不该等）
- 是否把"多集规划"塞进了单条需求？（先出第 1 条）

### 1.1 降级分支（信息严重不足时）

不加轮、不拒绝出包：
1. 按默认值出包，缺失项全部标「未核实 / 待你确认」，结论写「草案」并列出解除条件。
2. 必须保留的事实（台词、品牌、真人授权）缺失时，相关单元留空或写「待补」，不得编造。
3. 用户在第 3 轮之后又要改，视为新请求：冻结上一包，只改点名单元。

---

## 2. 问题库（只问这三类，且带默认值）

### 2.1 交付形态
> "你要一条，还是一组连续镜头？默认：一条。"

判定：用户说"短剧/广告/一集/系列/下一集" → 序列或多集；否则单条。

### 2.2 目标模型
> "跑哪个模型？Seedance 2.0 / 2.5、Veo、MiniMax、Kling，或者说'通用'。默认：Seedance 2.0。"

用户不知道模型 → 用**通用方言**（不绑定平台语法），并在参数节标"未核实"。
用户给了平台名（即梦/可灵/海螺/Runway）→ 映射到模型档案；映射不确定时说明。

### 2.3 必须保留的事实
> "有没有必须原样保留的台词、品牌名、真实人物，或者不能出现的内容？默认：没有。"

这条决定三件事：台词是否逐字锁死、是否触发真人/品牌合规分支、负面约束写什么。

**问完就停。** 不要追加"画幅要 16:9 还是 9:16"——按用途默认（短剧/口播 9:16，广告/电影感 16:9），写进决策摘要让用户改。

---

## 3. 第 1 轮信息够不够的判定

够用（直接出包）：
- 有一个可拍摄的主体 + 一个动作或事件；
- 或者有一份剧本/分镜文本。

不够用（才问，且只问缺的那一项）：
- 只有氛围词，没有主体（"要一个很燃的视频"）→ 问"谁在做什么"；
- 只有主体，没有发生什么（"拍我的猫"）→ 问"它要做什么/你要什么情绪"；
- 剧本里关键事实互相矛盾（同一人两个名字、时间跳变）→ 指出矛盾，给一个默认解读，让用户在第 3 轮改。

**不要**因为"信息不完整"就拒绝出包。缺的用默认值补，标注出来即可。

---

## 4. 项目状态（仅 Full Lane 需要）

单条 Fast Lane 不建文件。以下情况建项目目录：

- 多镜序列（>1 条）需要跨条连续性；
- 多集/系列；
- 客户交付，需要回滚与证据；
- 涉及真人 / 品牌 / IP 合规审查，需要留存授权与决策证据；
- 用户明确说"继续上次的"。

目录约定：

```text
<project>/
├── brief.md          # 原始输入，逐字保存，不改写
├── decisions.md      # 已确认决定（谁定的、什么时候、影响什么）
├── plan.json         # 结构化计划：条数、时长、镜号、素材绑定
├── continuity.md     # 连续性台账：人物状态、道具归属、空间方向、光线状态
├── package-01.md     # 每条的生产包（8 节）
└── review.md         # 生成后的实际观察与修复记录
```

**状态机**（借自社区生产型 Skill 的做法）：

```text
planned → assets-ready → submitted → generated → reviewed
```

- `planned`：只有文本包，没素材。
- `assets-ready`：素材编号与挂图计划齐了，但还没生成。
- `submitted` / `generated` / `reviewed`：只有用户真的去跑了才允许标。
- **永远不要把"提示词写完了"说成"视频做好了"。**

### 4.1 plan.json 最小结构

```json
{
  "project_id": "proj-001",
  "model": "seedance-2.0",
  "aspect": "16:9",
  "segments": [
    {
      "id": "S01",
      "duration": 15,
      "shots": [
        {"id": "S01-01", "t0": 0, "t1": 5, "size": "全景", "move": "缓推",
         "action": "角色推门进入", "exit_state": "门半开，人站在门内左侧"}
      ]
    }
  ],
  "assets": [
    {"id": "A01", "name": "主角-正面", "role": "identity", "scope": ["S01-01", "S01-02"]}
  ]
}
```

字段解释见 `assets/schemas/plan.schema.json`。

## 5. 第 3 轮补丁协议

用户说"改第 2 条""换运镜""台词太长"时：

1. 先回一行：**本轮只改：S01-02；其余未动。**
2. 只重写被点名的单元（一条提示词 / 一镜的分镜行 / 一段台词预算）。
3. 若改动会影响相邻镜头（例如改了出点状态），**必须点名**并给两个选项：只改本镜（可能接不上）/ 连带改下一镜入点。
4. 重跑结构自检，只报受影响项。
5. 不改镜号、不重排顺序、不清空 decisions.md。

**禁止**"顺手优化"：用户没点名的地方，逐字保持。

---

## 6. 跨会话续写

用户下次说"继续"时：

1. 读 `brief.md` + `decisions.md` + `continuity.md` + 最新 `package-*.md`；
2. 只问一句："从第 N 条之后继续，还是先改上一条？"
3. 已接受的决定不重问；`decisions.md` 里标 `accepted` 的视为已定。
4. 上一轮标了"未核实"的外部事实，如果仍然影响结果，再提一次，不要假装已经核实。

---

## 7. 权威顺序（冲突时按此裁决）

1. 安全、版权、真人授权、平台政策
2. 目标模型的已核实边界（未核实的不当硬约束）
3. 用户明确说出的不可让步项
4. 素材职责与"不得传递"清单
5. 连续性（身份、空间、时间、道具归属、声音状态）
6. 物理因果与动作可读性
7. 镜头与剪辑逻辑
8. 风格、色调、氛围、装饰细节
9. 本 Skill 的默认值（最先让步）

**同一层内**：已核实的优先于推测的，用户说的优先于默认的；仍打平就问一句，不要替用户赌。

裁决后必须说明牺牲了什么，例如：
> "借用参考视频的运镜会遮住交接动作，所以改成更浅的推轨；台词时长不变。"

---

## 8. 不该问的问题清单（硬禁）

- 焦段、光圈、灯位、色温（你定）
- 景别、运镜、构图（你定）
- 音色、BGM 风格、音效清单（你定，用户可改）
- 输出分辨率、码率（按模型默认，写进参数节）
- "要不要我顺便写资产图提示词"（需要就直接写进 §5，不需要就说明没写）
- 任何能让用户感觉在填表的问题

---

## 9. 审稿模式

用户给已有提示词或生产包并说"审一下"时，不走创作三轮：

1. 先逐字读输入，不改写原文；台词与已确认决定视为已定。
2. 第一步固定为安全筛查（R-12）：真人授权、未成年人、IP、品牌；违规单元先标出，审稿建议不得把它"最小改动"成合规样子以外的违规写法。
3. 按 `06_质量与自检.md` 的 S 项与 R 项逐项核对，问题按编号列出并写证据（哪一节、哪一镜、原文哪一句）。
4. 输出只有两部分：问题清单 + 最小改动建议；只改有问题的单元，其余逐字不动，不重排镜号。
5. 无法判断的项写「待人工评估」，不打分、不编造模型参数；参数节未核实项照实标出。

## 10. 七阶段状态机（3 轮契约的扩展）

> 本节是 `SKILL.md` §1 三轮契约的扩展：阶段划分是工作流程约定，不是任何平台的官方流程。触发例句为识别信号示例，不是用户原话的统计。证据等级 C 级（项目内约定，未核实）。冲突时以 3 轮契约（`SKILL.md` §1）为准。

### 10.1 阶段总览与 3 轮契约的对应关系

| 阶段 | 名称 | 对应 3 轮契约 | 说明 |
|---|---|---|---|
| 0 | 需求澄清 | 第 1 轮前半 | 收内容、问 ≤3 个阻塞问题、给默认值、判 Fast Lane |
| 1 | 风格探索 | 第 1 轮后半 | 风格候选与选定（见 10.2 注记） |
| 2 | 模型选型 | 第 1 轮后半 | 目标模型 + 参数包（含证据等级标注） |
| 3 | 初稿生成 | 第 2 轮 | 一次性出完整 8 节生产包 |
| 4 | 细节调优 | 第 3 轮 | 只改点名单元，差量修改 |
| 5 | 批量生产 | 第 3 轮之后（Full Lane） | 单条确认后扩展为批量；须建项目状态（见 §4） |
| 6 | 后期整合 | 交付前（Full Lane） | 剪辑建议与色彩统一核查，不生成成片 |

### 10.2 各阶段逻辑（触发信号 / 策略 / 输出 / 退出条件）

**阶段 0 · 需求澄清**：触发如「帮我写一个视频」「我想拍个短片」「给我做条 30 秒广告」。策略：≤3 个阻塞问题 + 默认值；先判断 Fast Lane 条件，满足则直接跳阶段 3。输出：确认单（题材 / 风格 / 模型 / 时长 / 资产状态），每项标「用户给定」或「默认值」。退出：确认单完整，或 Fast Lane 触发，或输入严重不足 → 走降级分支（按默认值出「草案」并列解除条件）。

**阶段 1 · 风格探索**：触发如「换个风格」「多给几个风格看看」。策略：给 2–3 个 STYLE LOCK 候选（`templates/styles/` 优先）+ 简要对比说明（各适合什么戏路、各有什么代价）。输出：选定 STYLE LOCK + 光色逻辑，写入决策摘要。退出：用户一句话选定；用户不选定则保留默认值并标明，不得反复追问。

> 注记：阶段 1「给候选」与 3 轮契约第 1 轮「不让用户选风格」之间存在张力。本 Skill 口径：阶段 1 的候选只在确认单完成后出现，且只给 2–3 个带对比说明的候选、由用户一句话定；不得在第 1 轮开头抛风格菜单让用户填表。冲突时以 3 轮契约为准。

**阶段 2 · 模型选型**：触发如「这条换 Veo」「哪个模型拍人脸最好？」「换个便宜点的」。策略：参照 `references/03` 模型参数差异表，给推荐 + 备选 + 局限说明（含证据等级）；触发方言转换时按 `references/03` §13 的转换引擎五步重编译执行层，故事层逐字不动。输出：目标模型 + 参数包（含证据等级标注与核验日期；未核实项标「未核实」）。退出：模型确定；换模型后须重跑结构自检。

**阶段 3 · 初稿生成**：触发如「就按这个出吧」「直接出生产包」。策略：按 8 节生产包格式一次性输出，缺一节不算交付；审稿模式除外。输出：完整生产包；参数节每项带证据等级与核验日期。退出：生产包交付并通过结构自检；用户反馈问题 → 阶段 4。

**阶段 4 · 细节调优**：触发如「脸太 AI 了」「这镜的光不对」「只改第三镜背景」。策略：识别反馈类型（去 AI 感 → `references/09`；一致性 → `references/04` §12；运动学/物理 → `references/09` §4；风格偏离 → STYLE LOCK 复核）→ 只改点名单元；差量句先列不动维度再写唯一诉求（见 `references/08` §3 第 1 条）。输出：差量修改包，标明「哪处变了，哪处不变」；改动影响相邻镜头时必须点名并给两个选项（只改本镜 / 连带改下一镜入点）。退出：用户确认修改；新反馈 → 留在本阶段继续；用户要求推翻已确认决定 → 回到阶段 0，不得在阶段 4 内擅自推翻。

**阶段 5 · 批量生产**：触发如「批量生成 20 条」「按这个模板再做一集」「下一集继续」。策略：保持 STYLE LOCK 不变 + 批量模板 + 自检脚本验证；须建项目状态（项目目录与连续性台账，见 §4）；单条 Fast Lane 不建文件。输出：批量生产包 + 命名规范列表（资产命名见 `references/04` §11）。退出：批量包全部通过自检；某条失败 → 按 §9 失败归档流程归档，不得只改提示词不留记录。

**阶段 6 · 后期整合**：触发如「都生成完了，怎么拼？」「颜色每段不太一样」。策略：J-cut / L-cut 建议（声音先入 / 画面先切，见 `references/02` §7、§15）、音画同步检查、色彩统一性核查；输出剪辑建议单，不生成、不剪辑成片（本 Skill 为文本工具）。输出：剪辑建议单 + 待补拍清单（缺的镜头、缺的衔接帧逐项列出）。退出：建议单交付；补拍需求 → 回到阶段 3（只补点名镜头）。

### 10.3 Fast Lane（快速通道）

- **条件（须同时满足）**：有完整剧本 + 明确模型 + 无 IP 风险。
- **路径**：阶段 0 确认单 → 直接进阶段 3，**从触发到输出生产包 ≤2 轮交互**（第 1 轮：确认单确认；第 2 轮：完整生产包）。第 1 轮中 ≤3 个阻塞问题照常适用；无阻塞问题时第 1 轮可直接确认为「零问通过」，不得为凑轮次而提问。
- **不满足条件时**：不得走 Fast Lane；缺剧本 → 阶段 0 补确认单，缺模型 → 阶段 2 选型，有 IP 风险 → 先过安全边界（`SKILL.md` §0 第 4 条），三者缺一即不构成 Fast Lane。
- **安全边界不参与 Fast Lane 豁免**：任何阶段转换都不得绕过内容安全筛查（R-12）；安全筛查在阶段 3 输出前必做，Fast Lane 也不例外。

### 10.4 阶段识别与转移规则

1. **显式跳转优先**：用户点名阶段动作（「换模型」「批量」「只改第三镜」）时，直接进入对应阶段，不按顺序走。
2. **反馈优先于新需求**：同一句话既含反馈又含新需求时，先处理反馈（阶段 4），再问新需求是否进入阶段 0。
3. **回退只回阶段 0**：推翻已确认决定、更换题材/主角、更换 STYLE LOCK 体系时，回到阶段 0 重建确认单，不得在原阶段内「顺手」改掉根基。
4. **阶段不明时问一句**：信号模糊（例如「再改改」未点名单元）时，问一句确认单元与范围，不得猜测后直接改。
5. **每阶段输出须标明阶段**：回复开头或决策摘要里写清当前阶段（如「阶段 4 · 细节调优」），让用户随时知道自己在哪一步、怎么回退。
