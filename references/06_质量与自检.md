# 06 · 质量与自检

> 核心原则：**能本地证明的才阻断，审美判断交给人。**
> 把"好不好看"写成脚本规则，会把导演判断僵化成表单——社区已经踩过这个坑。

---

## 1. 四级规则

| 级别 | 前缀 | 谁来判 | 能否阻断交付 | 例子 |
|---|---|---|---|---|
| 结构不变量 | `S-` | 脚本 | 能（FAIL） | 时间轴加不平、引用不存在的素材、台词被改、占位符丢失 |
| 复核不变量 | `R-` | 人 | 能（要求返工） | 台词与说话人对应、素材职责串镜、连续性状态矛盾 |
| 工艺默认 | `C-` | 人 | 不能（用户可覆盖） | 三镜结构、缓推、浅景深、先建立后推进 |
| 审美选项 | `T-` | 人 | **不能** | 色调、风格词、节奏偏好 |

**规则**：
- 脚本只能执行 `S-`。
- `C-` 被当成硬规则执行 = 差两级，属于设计错误。
- `T-` 永远不能单独阻断交付。

## 2. 结构项（脚本可判，`S-`）

| ID | 检查 | 失败含义 | 修法 |
|---|---|---|---|
| S-01 | 8 节齐全（审稿模式除外，见 `00_交互协议.md` §9） | 交付不完整 | 补齐缺失节 |
| S-02 | 每条有时间轴，且从 0s 开始 | 模型不知道多久 | 重写时间轴 |
| S-03 | 镜长之和 = 条时长（±0.5s） | 时间对不上 | 调镜长或改条时长 |
| S-04 | 每镜有非空主动作 | 动作格空着 | 补动作或删该镜 |
| S-05 | 台词逐字出现在事实层 | 台词被改写 | 回事实层核对 |
| S-06 | 台词字数 ≤ 预算（或标"超时"） | 说不完 | 拆镜/延长，不删台词 |
| S-07 | 引用编号在素材表里存在 | 引用了不存在的图 | 补素材或删引用 |
| S-08 | 同一段不混用模型语法 | 模型忽略其一 | 统一语法 |
| S-09 | 参数不泄漏进提示词（MiniMax H3 例外） | 模型把参数当内容 | 移到参数节 |
| S-10 | 模板占位符 `{{…}}` 未被破坏 | 模板失效 | 原样保留 |
| S-11 | 素材作用镜头范围合法 | 绑定错镜 | 修范围 |
| S-12 | 镜号唯一且连续 | 引用错位 | 重编号（仅新建时） |
| S-13 | 每份素材写了主职责与「不得传递」 | 职责不明 | 补两列 |
| S-14 | 提示词块内无解释性文字 | 复制时会带进模型 | 解释移到块外 |

脚本：`scripts/check_package.py`，逐项输出 PASS/WARN/FAIL。

## 3. 复核项（人判，`R-`）

| ID | 检查 | 怎么判 |
|---|---|---|
| R-01 | 台词保真：逐字、顺序、重复次数、说话人 | 对照原文逐条核 |
| R-02 | 动作可在原文/输入中找到依据 | 不无中生有 |
| R-03 | 素材职责与"不得传递"一致 | 每维度一个所有者 |
| R-04 | 连续性：人物位置、道具归属、光线状态、屏幕方向 | 前后镜对照 |
| R-05 | 每镜一个主运镜，且有动机 | 问"为什么动" |
| R-06 | 动作物理可信（接触、重量、路径） | 想象实拍能不能做到 |
| R-07 | 风格与材质一致（非写实不套写实词） | 检查形容词与材质 |
| R-08 | 时长分配符合戏剧重量 | 高潮/反应有没有时间 |
| R-09 | 声音与画面同步点清楚 | 关门/落点/台词起止 |
| R-10 | 没有把"未核实"写成"确定" | 查参数节证据列 |
| R-11 | 每镜只有一个主动作 | 数一数动作格里有几个并列动作 |
| R-12 | 内容安全：真人授权 / 未成年人 / IP / 品牌 | 查事实层授权记录；无授权则通用化描述；复刻原作、换脸冒用、未成年人写实或性化一律标「需修改」并拒改违规单元 |

复核结论只有三种：`通过` / `需修改` / `需人工看成片`。**不打分**。「需人工看成片」即入口 `SKILL.md` 所称「待人工评估」，同一含义，两种写法。

## 4. 失败修复阶梯

按顺序试，不要跳级：

```text
1. 改动作链（起点→触发→变化→落点）
2. 减同时发生的事件（一镜一个主动作）
3. 明确素材职责与"不得传递"
4. 压时长 / 拆条
5. 换输入模式（T2V ↔ I2V ↔ 参考）
6. 换模型或换平台
7. 后期修（剪辑、局部重绘、补拍）
```

| 症状 | 最可能原因 | 第一动作 |
|---|---|---|
| 动作做一半停了 | 动作链缺落点 | 补终点状态 |
| 人物换脸 | 素材职责不清 / 多图冲突 | 一人一图，写不得传递 |
| 镜头乱切 | 一镜多运镜 / 镜内换空间 | 留一个主运镜 |
| 台词被吞 | 字数超预算 | 拆镜或延长 |
| 画面很糊/很乱 | 事件密度过高 | 减事件，不加形容词 |
| 风格不统一 | 风格词抽象 / 光线逻辑冲突 | 换成材质+光向+运动 |
| 模型报错 | 参数越界 / 敏感表述 | 查边界，换等价说法 |

## 5. 自检报告格式

```markdown
## 7. 自检

### 结构项（脚本）
- S-01 PASS · S-02 PASS · S-03 FAIL（15.0s vs 14.0s）…
- FAIL 项修法：…

### 复核项（人）
- R-01 通过：台词 3 条逐字一致
- R-04 需修改：S01-02 人物左右与 S01-03 相反
- R-06 需人工看成片：雨滴落在伞面的物理

### 结论
可交付 / 修完再交 / 只能当草案
```

## 6. 真实性边界（写进每次交付）

- 结构 PASS ≠ 成片好看；只证明文本自洽。
- 模型参数未逐台实测，平台/版本/账号可能不同。
- 情绪、口型、物理、材质只能人工看片判断。
- 不提供"保证高质量""一次过"的承诺。

---

## 7. 什么时候可以不给结论

以下情况**不要**硬下"可交付"：

- 用户还没给素材，但包里有引用；
- 台词预算标了"超时"；
- 参数节有 `未核实` 且会影响结果；
- 用户要求的效果超出模型已核实能力。

写法：`结论：草案（待素材/待确认）`，并列出解除条件。

## 8. 无代码人工对账清单（无 shell 时用，不得谎称已跑脚本）

按 S-01…S-14 逐项人工核对，核完在自检节写「脚本未跑，人工对账完成」并列出未通过项：

| 组 | 人工核对动作 | 对应 |
|---|---|---|
| 结构 | 8 节齐全；每条时间轴从 0s 起；镜长之和 = 条时长（±0.5s） | S-01…S-03 |
| 动作 | 每镜有且仅一个非空主动作 | S-04、R-11 |
| 台词 | 事实层台词与原文逐字一致；字数 ≤ 预算或已标"超时" | S-05、S-06 |
| 引用 | 每个引用编号都在素材表里；素材写了主职责与「不得传递」 | S-07、S-13、S-11 |
| 语法 | 同一段只用一种模型语法；参数未泄漏进提示词（MiniMax H3 时间码除外） | S-08、S-09 |
| 模板 | 提示词块内无解释文字；模板 `{{…}}` 未被破坏或改名 | S-14、S-10 |
| 合规 | R-12：事实层有真人授权记录或通用化描述；无换脸冒用、未成年人写实或性化、IP 复刻、品牌冒用 | S-07、S-13、S-11、R-12 |
| 编号 | 镜号唯一且连续 | S-12 |

人工对账只能证明文本自洽，不能证明成片好看；结论仍按 §5 写，人工项标「待人工评估」。

## 9. 失败归档流程

> 目标：失败可查、可复用、可触发去 AI 感策略库更新。归档失败案例不是「记流水账」，而是给下一条提示词留规避依据。归档的是流程与字段，历史案例原文不收入本 Skill。

1. 失败发生后 1 个工作日内建档（离线归档，以归档日期为准）。
2. 按字段逐项填写；「未核实」字段不得留空谎填，写「未核实」。
3. 判定缺陷类别（对照 `references/09` §2 的 8 类）；类别无法判定 → 写「待分类」，不得硬套。
4. 写出规避动作（改提示词的哪一句、改后期哪一步、改选材哪一项），并链接到 `references/09` 对应类别。
5. 归档后检查：同一失败类型重复出现 ≥2 次 → 触发 `references/09` 该类别复核（人工触发）。

必填字段：case_id、title、source_record_id、category、evidence_level、failure_description、root_cause、avoidance_action、kb_link。选填：model、prompt_excerpt、verification_status。
