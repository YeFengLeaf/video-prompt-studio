## 1. 证据等级

| 等级 | 含义 | 用法 |
|---|---|---|
| **A** | 官方文档/官方博客直接写明 | 可写入参数节，注明来源与日期 |
| **B** | 官方文档的社区转引（有链接、可复查） | 可写入，标"转引" |
| **C** | 项目内约定 / 多篇教程一致但无官方原文 | 只能当默认值，必须标"未核实" |
| **D** | 单一作者经验 | 只作提示，不写成规则 |

**核验日期**：2026-10-20。平台改版后必须重新核。

**过期规则**：生产包参数节必须写核验日期；核验日期超过 30 天，交付时写「需复核」，不得当作现行事实。未核实项的核验日期列填「未核实」，基准核验日期为本节首行的 2026-10-20。`check_package.py` 不判日期过期，过期提示靠人工与参数节文字。

## 3. Seedance 2.0

### 3.1 能力边界
- 单条 4–15 秒；多镜、原生音频、音画同步。
- 参考：图 ≤9、视频 ≤3（单条 2–15s）、音频 ≤3（单条 ≤15s）、合计 ≤12。
- 分辨率区间 480p–720p（按平台）。
- **平台合规**：不要上传/描述写实真人脸部素材，会被拦截。

### 3.2 提示词方言
结构顺序（官方示例与社区一致）：

```text
输出目标（要什么样的片子）
→ 参考映射（每个 @ 素材负责什么）
→ 主体与场景锚
→ 动作的时间推进
→ 镜头计划
→ 光线/材质/风格锚
→ 声音计划
```

写法：
- 导演式自然语言，允许 `Setting:` `Action:` `Camera:` `Style:` `Audio:` 这类短标签。
- 时间轴用 `0–3s：…` 分段，10 秒以上强烈建议分段。
- 每个 `@` 必须写**用途**：`@Image1 作为主角外观`，不能只写"参考 @Image1"。
- 参数（时长/画幅/分辨率）**不写进提示词**。

### 3.3 示例骨架（中文）

```text
{{主体}}在{{场景}}，{{动作起势}}。
0–4s：{{建立镜头}}，{{主体状态}}。
4–9s：{{主动作}}，{{阻力/变化}}。
9–15s：{{落点}}，{{收束画面}}。
镜头：{{景别}}，{{机位}}，{{主运镜}}。
光线：{{主光源方向}}，{{明暗关系}}。
声音：{{环境底噪}}；{{动作音}}；{{台词}}。
参考：@Image1 负责{{职责}}；@Video1 负责{{职责}}。
```

## 4. Seedance 2.5

相对 2.0 的增量（官方强调）：
- 单条最长 **30 秒**；长镜与连续性更强。
- 支持 **edit**（改局部、保其余）与 **extend**（续写）。
- 参考控制更细：视觉 / 视频 / 音频分别索引。

写法差异：
- 30 秒不要平均切三段；按"信息点"分，30 秒最多 3–4 个信息点。
- 续写：明确"从哪个状态继续"，不复述已完成动作。
- 编辑：先写"保留什么"，再写"只改哪一处"。
- 平台相关值（如 fal 的 4–30s / 480p–1080p / 21:9–9:16 / 参考数量）**只在确认平台后使用**。2026-10-27 复核：fal 2.5 参考模式 API 页面的分辨率枚举为 480p / 720p / 1080p（原表只写 480p / 720p，已更正，见 §11）。

## 5. Veo 3 / 3.1

**单条时长（2026-10-27 官方复核）**：Veo 3.1 为 4 / 6 / 8 秒；使用参考图、1080p 或 4K 分辨率时须选 8 秒。画幅 16:9 / 9:16；分辨率 720p / 1080p / 4K（4K 仅 Veo 3.1 Preview 模型）。参考图最多 3 张（仅 Veo 3.1）。此前本库"未记录确切上限"的写法已作废，以上为准（来源见 §11）。

### 5.1 方言
五段式（Google Cloud 指南）：

```text
[摄影] + [主体] + [动作] + [环境] + [风格与氛围]
```

- 摄影：镜头运动 + 构图（`dolly shot`、`tracking shot`、`close-up`、`low angle`）
- 音频：对白用引号；`SFX: …`；`Ambient noise: …`；不要对白就直接写"无对白"
- **负面提示**用"描述所缺"而不是抽象否定：
  - 好：`a desolate landscape with no buildings or roads`
  - 差：`no man-made structures`

### 5.2 中文场景
Veo 对英文更稳；中文台词可保留原文，但镜头与声音描述建议英文。用户要中文成片时，提示词语言与台词语言分开处理。

## 6. MiniMax H3

**唯一的"参数在提示词内"例外**：它要求严格 schema。

> 来源更正（2026-10-27）：本节 schema 与模式名以 MiniMax 官方 GitHub 仓库 `MiniMax-AI/MiniMax-H3` 的 `h3-prompt-writing` Skill 为准（已打开复核：三字段、五种模式、`<Picture 1>` 等标签、4–15 秒均见该 Skill 正文）。原"官方 HF 指南"说法作废。§6.2 的关键帧前缀句式出自该 Skill 的 `references/base-en.txt`，本次未逐字打开该文件，见 §11。

### 6.1 三字段（T2VA）

```text
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

### 6.2 关键帧模式前缀

```text
I2VA: For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

FL2VA: How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark; Picture 2 (from Shot N) aligns with the S.SS-second mark.

L2VA: How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark.
```

### 6.3 时间码
- `[Shot 1]` 不写时间码，从风格与初始构图开始。
- 后续镜头：`[Shot 2] At 00:03.500, the camera cuts to…`
- 时间严格递增，两位小数，落在有效时长内。
- 只有"增加新主体/空间/状态/视角/时间"才切；小距离变化用运镜。

## 8. 通用方言

用于：用户不知道模型、或目标是表中没有的平台。Runway / Pika / Sora / Wan / LTX 已有档案，见 §12，不走通用。

- 不写 `@Image1`、`[Shot 2]` 这类平台语法；
- 用自然语言写"参考图 1 负责…"；
- 时长按 15 秒内规划；
- 参数全部外置，并标"按你的平台填写"。

## 9. 方言切换协议

同一分镜换模型时，只改这五处：

| 层 | 改不改 | 说明 |
|---|---|---|
| 事实层（人物/场景/台词/动作） | **不改** | 台词逐字，动作不变 |
| 分镜表（镜号/时间/景别/运镜） | 基本不改 | 只有模型上限差异导致拆条时改 |
| 提示词结构顺序 | 改 | Seedance：目标→参考→主体→动作→镜头→光→声；Veo：摄影→主体→动作→环境→风格 |
| 引用语法 | 改 | `@Image1` / `<Picture 1>` / 自然语言 |
| 参数位置 | 改 | MiniMax H3 时间码进提示词；其余外置 |

**验收**：切换后故事层逐字一致；执行层五处全部对应；参数无泄漏。执行细则（转换引擎五步）与验收三条见 §13；方言骨架见 `references/方言骨架/`。

### 12.1 Runway Gen-3（A，官方资源页；046 为 C 未核实）

> G7 复核注（2026-10-27）：未找到 Gen-3 的官方帮助/文档页（当前官方文档只覆盖 Gen-4/4.5），本节数值未在官方页复核，维持原等级与原值，不得升级。Gen-4/4.5 的数值不得用来证实 Gen-3。

- **镜头提示词公式**（041，A）：`[Shot size] + [Angle] + [Movement + direction + speed] + [Subject & action] + [Lens/look] + [Lighting/mood] + [What the shot reveals]`。每个运动词必须带速度或时长修饰。单镜只可靠执行一个运动，多段运动需分镜拼接。
- **静态镜头锁定句**（042，A）：官方推荐原文：*"The camera is entirely motionless for the duration of the scene, with movement only occurring from the subject."* 同时要在画面里描述应发生的运动（元素入画/出画）给模型能量出口；残留轻微漂移建议后期稳定，不必重跑。大远景/建立镜头最易出现意外漂移，是最难落地的指令类型。
- **双写事故 double-directing**（043，A）：prompt 文本与 Camera Control 面板设置冲突会导致扭曲运镜。规避：运动路径只保留一个真相源——用面板管精确路径，prompt 只写风格、情绪与叙事目的；多段复杂编排拆成单独 clip 分别生成再剪。
- **写实四要素 + 速度词黑名单**（044，A）：四要素：①主体细节 ②运动描述（相机与主体）③光照与环境 ④物理材质线索；总长 20–50 词；光照必须带方向 `from [direction]`。速度只用 slow / gradually / gently / steadily / deliberately；明确禁用 quickly / rapidly / fast / suddenly（官方称常导致 erratic motion）。重量词：`Heavy [object] moves slowly`、`Light [object] drifts`、`With weight`。静态写法：`Static locked shot` / `Fixed camera` / `Locked frame`。顺序动作：`First [action], then [action]`。复杂人物交互、快速运动、可读文字、>10s 长一致性仍是弱项，建议多个 5 秒短 clip 拼接。
- **Motion Brush**（045，A）：涂刷方式圈定画面局部并指定方向与数值，只让该区域运动；Multi-Motion Brush 支持同图最多 5 个区域各自独立运动参数。它控制的是画面内主体运动，与 Camera Control 的相机运动是两个通道，同区域避免重复指定。
- **Camera Motion 面板**（046，C，**未核实**）：第三方教程称 Gen-3 有面板化 Pan/Tilt 确定性运镜，面板运镜与 prompt 关键词二选一。单一博客经验、未交叉验证当前 UI，不得当作已核实事实。

> **停用状态（2026-10-27 官方复核）**：OpenAI 官方系统卡注明「Sora 产品自 2026-04-26 起不再提供」；OpenAI API 模型页注明「Sora 2 模型与 Videos API 已于 2026-09-24 关闭，不再提供，无一对一替代 API」。以下档案为**历史口径**，仅供已生成素材的复盘参考，**不得作为当前可用平台出包**。API 实际提供的分辨率仅 720p（横 1280×720 / 竖 720×1280），示例中的「4K」写法是展示级示例文本，不是平台档位。

- **v1 段落式方言**（052，A，历史口径）：提示词 = 电影场面描述长段落，相机写成动作句，胶片/镜头参数直接嵌句。官方示例句式：*"The camera follows behind a white vintage SUV…"*、*"The camera rotates around a large stack of vintage televisions…"*；镜头参数直接入句：`shot on 35mm film`、`cinematic film shot in 70mm, depth of field, vivid colors`、`Drone view`、`the low camera view`；一条 prompt 内可写多镜头。
- **官方承认的失败边界**（053，A）：精确相机轨迹、左右方位、因果物理。规避：不写长串复合精确运镜轨迹，改用分镜单镜；左右方位改为相对动作关系描述；复杂因果物理（咬痕、刚性物体交互）拆短镜或用参考视频（V2V）兜底；多实体场景加 `one/two` 数量约束防凭空冒人。
- **v2 shot-list 分节方言**（054，A，历史口径）：官方展示级示例分节：Primary Target & Visuals（动作先读、二读景观）；Format & Look 直接写时长/快门/画幅（如 `5.0s; 4K; 180° shutter; large-format digital sensor emulation with crisp micro-contrast; very fine grain; no gate weave`）；Lenses & Filtration；Grade / Palette（highlights / mids / shadows 分层）；Lighting & Atmosphere；Location & Framing；Sound 段嵌入台词；Optimized Shot List（1 shot / 5.0s 时间码）。示例为官方展示级高质量写法，非 API 参数文档。含真人肖像「角色」功能——使用真人形象需本人授权，注意肖像权与版权风险（安全边界同 R-12）。

### 12.4 Wan2.2（A，官方仓库 README；开源推理口径）

> G7 复核注（2026-10-27）：官方模型卡（Wan-AI/Wan2.2-TI2V-5B）已证实 TI2V-5B 的 5 秒 720P@24fps、`1280*704`/`704*1280`、I2V 尺寸随输入图、24GB/80GB 显存口径。A14B 的 `1280*720`、S2V-14B 的 `1024*704` 及 prompt extension 细节未在本页逐项打开，维持原值与原等级，见 §14。

- **推理尺寸参数**（055，A）：T2V / I2V-A14B 用 `--size 1280*720`；TI2V-5B 任务 720P 固定只能 `1280*704` 或 `704*1280`；I2V 的 `--size` 代表画面面积，宽高比跟随输入图片；S2V-14B 用 `--size 1024*704`；24fps。HF 模型卡在国内网络直连受限。
- **prompt extension**（056，A）：官方推荐用 Qwen 系模型扩写提示词再生成。命令加 `--use_prompt_extend --prompt_extend_target_lang 'zh'`；方法二选一：`--prompt_extend_method 'dashscope'`（DashScope API，需 API key——key 只从环境变量读，永不写入命令历史与输出文件；T2V 用 qwen-plus，I2V 用 qwen-vl-max，可配国际站 URL）或 `--prompt_extend_method 'local_qwen'`（本地 Qwen2.5-14B/7B/3B-Instruct 做 T2V，Qwen2.5-VL-7B/3B-Instruct 做 I2V）；`--prompt_extend_model` 可换扩展模型。I2V 甚至可 `--prompt ''` 纯靠图片扩写生成。
- **显存边界**（057，A）：14B 单卡官方要求 ≥80GB VRAM；OOM 规避组合 `--offload_model True --convert_model_dtype --t5_cpu`（把 T5 文本编码器放 CPU）；多卡用 FSDP + DeepSpeed Ulysses（`--ulysses_size 4/8 --dit_fsdp --t5_fsdp`）；TI2V-5B 单卡 24GB（RTX 4090）可跑，5 秒 720P 约 9 分钟内。80GB 是 A100/H100 级别门槛，普通显卡实际只能跑 TI2V-5B 或蒸馏方案。
- **官方禁忌**（058，A）：Wan-Animate（animation / replacement 双模式）任务保持基线权重，不挂 Wan2.2 系 LoRA；官方原话：*"we do not recommend using LoRA models trained on Wan2.2, since weight changes during training may lead to unexpected behavior"*。replacement 模式可用 `--use_relighting_lora` 官方指定重光照 LoRA。

### 12.5 LTX-2 / LTX-2.3（A，官方 docs + 仓库 README；区分 API 与开源口径）

> G7 复核注（2026-10-27）：Lightricks 官方 ltx.io 模型页已证实 Fast/Pro 的分辨率档（1080p/1440p/4K）、帧率（24/25/48/50fps）、Fast 最长 20s@1080p（1440p/4K 缩至 10s）、Pro 最长 10s 且为 audio-to-video/retake/extend 所必需。画幅 16:9/9:16、六要素提示词结构与开源参数细节（32 整除、8n+1、Guidance）未在官方页逐项打开，维持原值与原等级，见 §14。

- **提示词方言**（059，A）：六要素结构 + 单一流动段落 + 现在时 + 4–8 句。六要素：①Establish the Shot（匹配类型的电影景别词）②Set the Scene（光照/色板/材质/氛围）③Describe the Action（核心动作写成自然顺序流）④Define Characters（年龄/发型/服装/特征，情绪用身体动作表达，不写抽象标签如 sad）⑤Identify Camera Movement(s)（写明相机怎么动、何时动，并描述运动后主体的样子）⑥Describe the Audio（环境声/音乐/对白；对白放引号内，注明语言与口音）。细节密度匹配景别（特写比大远景更细）；相机运动相对主体描述。

- **扩展/蒸馏帧数规则**（061，A）：distilled 模型（0.9.6/0.9.7/0.9.8）官方明示不要求 classifier-free guidance 与 spatio-temporal guidance，推荐采样 8 步；视频扩展时输入视频段长必须是 8n+1（9/17/25…），目标帧数必须是 8 的倍数，否则被 -1 填充/裁剪错位。多条件生成用 `--conditioning_start_frames` 指定各参考素材的目标帧位，可配 conditioning strength（默认 1.0）。误用 CFG/STG 到 distilled 模型既浪费算力又破坏其蒸馏分布。
- **模型能力矩阵**（062，A，API 版）：LTX-2.3 支持竖屏+横屏至 4K、电影级帧率 24/48fps、image-to-video 首尾帧控制（first-to-last frame）；LTX-2 横屏至 4K、25/50fps、同步音频生成。变体：Fast（快/便宜，最长 20s@1080p/25fps，适合分镜迭代）与 Pro（高保真，audio-to-video / retake / extend 端点必需）。分辨率档：1080p（1920x1080 / 1080x1920）、1440p（2560x1440 / 1440x2560）、4K（3840x2160 / 2160x3840）；比例仅 16:9 与 9:16；时长档 6/8/10/12/14/16/18/20s（1080p），高帧率/高分辨率档缩至 6/8/10s。

## 13. 转换引擎五步与切换验收

> 转换引擎五步与切换验收三条为本 Skill 方法论约定（C 级），无外部来源。§9 的五处协议仍为准；本节是执行细则。

### 13.1 转换引擎五步

同一分镜换模型时，按顺序执行五步；故事层（事实层 + 分镜表）在五步中一字不动。

| 步 | 动作 | 规则 |
|---|---|---|
| 1. 结构顺序重排 | 按目标模型的结构顺序重写 §4 提示词的段落顺序 | Seedance：目标→参考→主体→动作→镜头→光→声；Veo：摄影→主体→动作→环境→风格；H3：三字段 schema。不得增删动作与台词 |
| 2. 引用语法替换 | 全量替换引用写法 | `@Image1` ↔ `<Picture 1>` ↔ 自然语言「参考图 1」；Kling 4.0 用 `@Element1`（2026-10-27 官方复核，原小写约定已作废）。同一段内只用一种语法（S-08） |
| 3. 参数位置判定 | 决定每个参数写在哪里 | 只有 MiniMax H3 的时间码进提示词；其余模型的参数（时长/画幅/分辨率）一律外置进 §6 参数节（S-09） |
| 4. 负面词转换 | 按目标模型改写负面约束 | Veo：抽象否定改「描述所缺」；Seedance：负面约束写进 §2 禁用项与 §4 约束行，不写「不要…」进提示词主体；H3：负面约束只出现在三字段的对应位置 |
| 5. 拆条适配 | 模型上限差异导致拆条时才改分镜表 | 目标上限 < 当前条长时拆条（须标「拆条适配」，镜号重编仅限新建包）；上限足够时分镜表逐字不变。拆条不得静默删台词 |

**五步禁令**：五步中任何一步都不得改事实层（人物/场景/道具/台词逐字）、不得改分镜表的镜号与时间（拆条适配除外）、不得把未核实参数写成已核实。

**新增模型的结构顺序**：Runway 用镜头公式顺序（景别→角度→运动→主体→镜头/光影→揭示）；Pika 用 subject→action→setting→style→camera move，negative prompts 另列；Sora 2 用官方 shot-list 分节（历史口径）；Wan2.2 用自然语言正文 + 命令行参数外置；LTX 用六要素单一流动段落。五步的第 1 步按目标模型执行，第 2 步的引用语法对新模型一律用自然语言（Runway/Pika/Sora/Wan/LTX 均无 `@`/`[Shot]` 式引用语法，面板与命令行参数不进提示词）。机械转换辅助见 `scripts/dialect_converter.py`（故事核逐字保留，未填参数一律 `[UNVERIFIED: to fill in]`，不编造数值）。

### 13.2 切换验收三条（校验清单）

人工或脚本（`scripts/check_switch.py`）验收切换结果，三条全部通过才算切换完成：

1. **故事层逐字一致**：两包的 §2 事实层与 §3 分镜表逐字相同（行尾空白与换行符差异不计；内容差异一律 FAIL）。验收工具：`python3 scripts/check_switch.py <包A.md> <包B.md>`。
2. **执行层五处全部对应**：§4 提示词结构顺序、引用语法、参数位置已按目标模型重编译（§13.1 第 1–3 步）；负面词已按目标模型转换（第 4 步）；拆条只在上限不足时发生（第 5 步）。
3. **参数无泄漏、无虚构**：§6 参数节证据等级与核验日期齐全，C/D 级标「未核实」；§4 提示词块内无参数（H3 时间码除外）；未核实参数未写成已核实（S-09/S-10 逻辑同 `check_package.py`）。

验收示例（Skill 样例对）：`01_single_story/output.md`（Seedance 2.0）→ `04_model_switch/output-minimax.md`（MiniMax H3），三条均通过；脚本退出码 0 = 通过、1 = 故事层不一致、2 = 文件错误。
