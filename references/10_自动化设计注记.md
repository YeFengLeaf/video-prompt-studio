**架构要点**：

1. **平台适配器隔离**：每个平台一个适配器，只负责「本平台的参数翻译 + 提交 + 状态查询」；上层只认统一的 prompt 格式（`{name, prompt, model, duration, resolution, refs}`），不得让平台方言泄漏到生产包的故事层（方言转换规则见 `references/03_模型适配.md` §13）。
2. **批量提交与状态分离**：提交只返回任务 ID，不等待完成；状态查询独立轮询；下载只下载已完成任务。三个步骤的失败互不掩盖：提交失败、查询失败、下载失败各记各的日志。
3. **重试有上限**：失败重试最多 3 次、指数退避；超限写入错误日志并停手，不得无限重试烧掉配额。
4. **日志不记敏感内容**：日志只记任务元数据，完整 prompt 不落日志（prompt 可能含隐私信息）。日志格式：`task_id / platform / model / prompt_hash / status / error / retry_count / created_at / completed_at`（`prompt_hash` 哈希算法实现时须选用标准哈希并记录算法，不得用可逆编码代替）。

## 4. 安全边界（硬约束）

1. **默认 dry_run**：所有生成类操作默认 `dry_run=True`（只验证参数，不实际提交）；用户明确 `--yes` 才执行。无 `--yes` 时的任何「已提交」声称均为虚假陈述。
2. **显式批准**：生成、上传、付费调用一律须用户显式批准；批准须指明范围（哪几条、哪个模型、大致预算），「都交给你」不构成付费批准。预算批准前须先报平台价格。
3. **密钥只从环境变量读**：API KEY 只从环境变量读取，不落日志、不落配置文件、不落文档、不落聊天记录。配置文件只放非敏感配置。
4. **参考图不经第三方中转**：上传的参考图直传目标平台，不经过第三方中转服务；中转会同时带来隐私与合规风险。
5. **本 Skill 自身不执行生成**：Skill 本体为文本工具（见 `SKILL.md` §0 第 1 条）；本文件描述的 CLI 只是未来自动化链路的设计，当前任何「已生成」的结果都不出自本 Skill。本文件不提供、不暗示任何绕过批准的执行路径。
